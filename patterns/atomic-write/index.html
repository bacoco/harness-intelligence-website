Un raté ne doit jamais effacer le dernier bon menuLeçonA failed attempt must not erase the last good menuLesson

Un changement est sûr quand il peut rater sans faire disparaître le dernier menu valable. Prépare, vérifie, puis échange. Tant que l’ancien reste lisible, un arrêt ne coûte qu’un retard.Une écriture de fichier généré n’est sûre que si un échec survenu avant commit laisse l’ancien fichier intact. La propriété à garantir est la survie de la dernière version connue bonne, pas la réussite du chemin nominal.A change is safe when it can fail without destroying the last menu known to work. Prepare, check, then swap. As long as the old board remains readable, a stall costs only time.A generated-file write is safe only when failure before commit leaves the previous file intact. The property to guarantee is survival of the last known-good version, not success of the nominal path.
